## `octolens onboard`

Set up Octolens for your company from the terminal: account, website, keywords, mentions, feeds, Slack and your AI tools. Under --json (or piped) it prints the setup's status envelope instead.

**Flags**

| Flag | Type | Required (headless) | Description |
|---|---|---|---|
| `--if-revision` | `string` | no | Refuse (exit 2, ONBOARDING_REVISION_CHANGED) unless the onboarding is still at this revision (the envelope's `revision`) |
| `--no-browser` | `boolean` | no | Never open a browser: print links instead |
| `--plain` | `boolean` | no | Append-only output: no in-place redraw, no animation (screen readers, logs) |
| `--wait` | `integer` | no | Seconds to wait for server work before answering (--json default 45, max 600; a TTY waits until done). A wait that runs out answers status "running" with a poll nextAction, exit 0. |
| `--yes` | `boolean` | no | Accept SAFE defaults without asking. Never removes a feed or writes MCP config on its own: those need their explicit flag too. |

**Examples**

```bash
octolens onboard
octolens onboard --json
octolens onboard --plain
```

Exactly one document on stdout and nothing on stderr. A refused request (a Sandbox workspace, a second trial, an existing account) prints NO stdout document: it exits non-zero with the error envelope on stderr, whose additive `nextAction` names the recovery (`octolens login` for EMAIL_ALREADY_REGISTERED, `onboard status` for RESPONSE_LOST). The agent loop is `onboard status --json`, then run `nextAction.argv`.

Without `--json`: A terminal runs the guided setup, step by step, and prints where the setup is when it stops. Piped or under `--json` it does not prompt: it prints the status envelope, exactly like `onboard status`.

## `octolens onboard feeds`

Step 4 of onboarding: review the feeds we made for you, rename or remove any, then go on to Slack

**Flags**

| Flag | Type | Required (headless) | Description |
|---|---|---|---|
| `--confirm` | `boolean` | no | Keep the feeds as they are now and go on to Slack |
| `--if-revision` | `string` | no | Refuse (exit 2, ONBOARDING_REVISION_CHANGED) unless the onboarding is still at this revision (the envelope's `revision`) |
| `--no-browser` | `boolean` | no | Never open a browser: print links instead |
| `--plain` | `boolean` | no | Append-only output: no colour, nothing redrawn (screen readers, logs) |
| `--remove` | `string` | no | Remove a feed by board number or id (repeatable; needs --yes) |
| `--rename` | `string` | no | Rename a feed: &lt;feed&gt;=&lt;name&gt;, where &lt;feed&gt; is its board number or id (repeatable) |
| `--wait` | `integer` | no | Seconds to wait while your feeds are still being made (--json default 45, max 600). A wait that runs out answers status "running" with a poll nextAction, exit 0. |
| `--yes` | `boolean` | no | Confirm --remove. On its own it never removes a feed. |

**Examples**

```bash
octolens onboard feeds
octolens onboard feeds --json
octolens onboard feeds --rename 2="Competitors" --confirm --json
octolens onboard feeds --remove 3 --yes --confirm --json
```

Without `--json`: A terminal prints the receipt: keywords, feeds, AI tools, the trial's start and end dates, and up to three next commands.

## `octolens onboard keywords`

Step 2 of onboard: review the keywords Octolens suggests for you, change any, and create your workspace

**Flags**

| Flag | Type | Required (headless) | Description |
|---|---|---|---|
| `--add` | `string` | no | Add a keyword: term[:type], type one of brand, competitor, industry (repeatable) |
| `--check` | `boolean` | no | Check the edited list against the server's rules; writes nothing |
| `--confirm` | `boolean` | no | Create the workspace with these keywords (the trial starts when setup finishes) |
| `--if-revision` | `string` | no | Refuse (exit 2, ONBOARDING_REVISION_CHANGED) unless the onboarding is still at this revision (the envelope's `revision`) |
| `--no-browser` | `boolean` | no | Never open a browser: print links instead |
| `--plain` | `boolean` | no | Append-only output: no in-place redraw, no animation (screen readers, logs) |
| `--remove` | `string` | no | Remove a keyword by its ref (k3), list number or text (repeatable) |
| `--rename` | `string` | no | Change a keyword: &lt;ref&gt;=&lt;new keyword&gt; (repeatable) |
| `--type` | `string` | no | Change a keyword's type: &lt;ref&gt;=brand\|competitor\|industry (repeatable) |
| `--wait` | `integer` | no | Seconds to wait for the suggested keywords (--json default 45, max 600; a terminal waits until they are ready). A wait that runs out answers status "running" with a poll nextAction, exit 0. |
| `--yes` | `boolean` | no | Accept SAFE defaults without asking. Never removes a feed or writes MCP config on its own: those need their explicit flag too. |

**Examples**

```bash
octolens onboard keywords
octolens onboard keywords --json
octolens onboard keywords --remove k3 --add 'growthbook:competitor' --check --json
octolens onboard keywords --rename k2='acme flags' --type k4=industry --confirm --json
octolens onboard keywords --confirm --json
```
